# team bots

[English](README.md) · [简体中文](README.zh-CN.md)

**在同一个任务看板中，协作管理多台 Paseo Host 上的 Agent。**

[Paseo](https://paseo.sh) 插件，用于跨机器指派任务、查看执行过程和汇总结果。只需在主控 Host 安装，手机或桌面连接主控后即可使用；主控也可以参与本机执行。

![架构示意：客户端连接主控，由主控管理本机及远端 Agent。](docs/images/team-overview.svg)

_图片仅为概念示意，角色、Host 与任务标签均为虚构内容。_

## 主要功能

- **紧凑任务工具栏：**返回、详情、成员和暂停使用图标，状态和活跃执行数保持可见。桌面悬停或键盘聚焦显示提示，触屏长按仅显示提示，不触发操作。

- **讨论时间线：**执行卡片紧跟触发评论，长评论和结果可原位展开。宽屏在右侧查看执行详情，窄屏在插件内全屏查看，返回保留草稿、展开状态和阅读位置。评论输入框位于底部，无需滚动到底寻找。
- **成员管理：**默认显示成员列表；项目目录与执行节点通过独立入口管理。英文界面统一使用 Bots。

- **统一任务看板**：待办、执行中、阻塞、待审核、已完成。
- **配置团队成员**：每个成员关联 Host、Runtime、具体模型、职责和默认目录，同一 Host 可配置多位成员。
- **评论指派**：通过 `@选择成员` 发送指令；不选成员时只保存讨论。
- **指派设置**：在“成员列表 → 指派设置”中设置每条评论的指派人数上限，默认不限。设置保存在主控上，不影响已有执行，也不是并发或排队设置。
- **保留会话上下文**：同一任务再次指派同一成员时，自动继续原会话；首次指派才创建。
- **查看执行记录**：统一查看消息、工具活动、权限请求和已保存的结果；完成后仍可查看历史。
- **暂停与纠偏**：冻结派发，确认中断后补充要求，只恢复选中的成员。
- **项目与附件**：关联各 Host 的 Paseo 项目，评论支持文本、Markdown 和图片附件。
- **中英文界面**：支持跟随系统、English、简体中文；用户内容和 Agent 输出保留原文。

## 协作方式

客户端复用现有 Paseo 连接访问主控。主控上的插件后台连接执行节点，保存任务与执行关联并收集结果；关闭手机或桌面客户端后，后台仍会继续协调。

无需额外部署协调服务，也无需在执行节点安装本插件。主控必须独立持有访问执行节点的授权；仅在手机中配对子 Host 不会自动授权给主控。支持 Relay 配对，无需 SSH。

![流程示意：指派、执行、暂停、补充要求，再继续原会话；每轮保留独立执行记录。](docs/images/session-flow.svg)

_每次指派都有独立执行轮次，并关联触发评论；续跑保留原会话上下文。_

## 安装

可以直接在主控 Host 从公开 Git 仓库安装：

```sh
paseo plugin add git:yeyan00/paseo-bots --ref v0.1.0
```

安装声明通过锁文件准备生产依赖，并禁用依赖生命周期脚本。官方插件目录收录与直接 Git 安装是两个独立流程。

主控需要 Paseo **0.11.4 或更新版本**、已启用插件，并具备 Node.js 和 npm。每个执行 Host 都需要运行中的 Paseo daemon，以及已认证、可用的 Agent Runtime。已在 Paseo 0.11.4 验证。

在**主控 Host** 克隆插件仓库并安装：

```sh
git clone https://github.com/yeyan00/paseo-bots.git
cd paseo-bots
npm ci
npm exec -- tsx server/install.ts
```

脚本通过已运行的本机 daemon 安装或重载插件，不重启 daemon。连接此 Host 的兼容客户端可从 Paseo 侧栏打开 **team bots**。包名和插件 ID 保持为 `paseo-team-tasks`。

## 配置并使用

![虚构数据的任务讨论与执行详情](assets/team-discussion-desktop.png)

上架截图使用实际插件组件、虚构示例数据和模拟 Host 响应，不包含真实 Host、项目或模型信息。验证范围见[发布验证说明](docs/release-verification.md)。
1. 打开「成员列表 → 执行节点」，使用执行节点的 Paseo Relay 配对链接添加 Host；主控本机已自动提供。
2. 添加成员，选择 Host、可用 Runtime、具体模型、默认目录和职责。
3. 打开「项目与目录」，添加协作项目，选择各参与 Host 对应的 Paseo 项目。可在选择器中登记已有目录，或新建 Host 项目。
4. 创建任务，填写目标和验收条件，选择协作项目。
5. 在底部输入框输入指令，通过「@ 选择成员」选择接收人并发送。点击讨论中的执行卡片查看过程和结果，也可通过任务顶部的成员摘要找到最新执行。
6. 检查实际交付文件和验证结果，再人工标记完成。

项目决定任务在各 Host 上使用的实际目录；未关联项目时使用成员默认目录。已有执行保留原目录。关联项目**不会自动同步文件**。

## 评论与执行

| 操作                 | 行为                                           |
| -------------------- | ---------------------------------------------- |
| 不选成员发表评论     | 只保存讨论，不向 Agent 发送消息。              |
| 首次指派任务中的成员 | 自动创建该成员的任务会话。                     |
| 再次指派同一成员     | 继续原会话，新增与本条评论关联的执行轮次。     |
| 成员执行中再次指派   | 排队，等待前一轮结束后执行。                   |
| 暂停任务             | 冻结派发并请求中断，排队项保持暂停。           |
| 继续并发送           | 继续选中的成员，未选成员及旧排队指派保持暂停。 |
| 停止单次执行         | 只中断该轮，其他排队项仍可能继续。             |

必须确认中断后才显示「已暂停」；节点离线等情况下保持「暂停中」。切换看板状态不会恢复运行。标记任务完成前，活跃执行必须已经结束或确认中断。

成员的 Host、Runtime/模型或实际目录发生变化时，会使用对应配置的独立会话。远端原会话不可用时会报告问题，不会静默替换会话并丢失上下文。暂停与停止保留文件及历史，不回滚修改，也不保证终止工具启动的脱离会话的后台进程。

## 附件与历史记录

桌面/Web 支持 UTF-8 文本、Markdown、JSON、CSV、YAML、日志和 PNG/JPEG/WebP/GIF 图片，每条评论**最多 4 个附件，单个最大 512 KB**。附件保存在主控，并随该次指派上传到执行节点；后续评论不会自动重发旧附件。

原生手机客户端可预览附件、粘贴内容创建文本附件；当前 SDK 接入尚未支持设备文件和相册选择。

会话历史每页最多读取 80 条，可按需加载更早记录。最终回复保存在主控；读取原始历史需要执行 Host 在线。打开远端原生 Agent 页面，还需要客户端直接连接该 Host。

## 持久化与恢复

默认数据目录为 `$PASEO_HOME/team-tasks`；未设置 `PASEO_HOME` 时使用 `~/.paseo/team-tasks`。可用 `PASEO_TEAM_HOME` 覆盖。
- `state.json`：任务、评论、成员/项目配置、执行映射和结果。
- `connections.json`：私有远端连接配置。
- `attachments/`：评论附件。

执行记录先落盘再派发，创建 Agent 使用固定幂等键。插件重启后对账已有映射；续跑消息送达不明确时查询会话记录，不盲目重发。

**同一数据目录仅允许一个主控插件实例使用。**同一 Host 的同一目录串行执行，不同 Host 可以并行。主控离线时，远端已启动的 Agent 可以继续；新派发与结果收集等待主控恢复。

插件是受信任代码，以 daemon 用户权限运行。连接凭据和实际任务数据应保存在代码仓库之外。当前不包含自动主 Agent 循环、DAG 调度、Git 合并或通用产物同步。

## 开发

```sh
npm run format
npm run typecheck
npm run lint
npm test
```

测试仅运行两个 Store/Coordinator 定向测试文件。修改源代码后，运行 `npm exec -- tsx server/install.ts` 重载插件。

主 Agent 可通过 CLI 调用正在运行的插件，不会另起一个协调后台：

```sh
npm run team -- help
npm run team -- snapshot
npm run team -- create task.json
npm run team -- comment comment.json
npm run team -- pause <taskId>
npm run team -- timeline <runId>
```

使用已配置成员 ID 的指派示例：

```json
{
  "requestId": "instruction-001",
  "taskId": "task-example",
  "body": "实现约定的修改，并报告验证结果。",
  "memberIds": ["builder", "reviewer"]
}
```

重试同一请求时保持 `requestId` 不变。确认暂停后显式继续任务，在评论参数中增加 `"resumeTask": true`。
